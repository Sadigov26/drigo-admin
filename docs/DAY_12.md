# Day 12 — Customer account tabs

Scope follows the customer sub-resources in Handbook Section 8.7 and the debt payment transition in Sections 5.6/8.8. The handbook groups work by module; the day numbering is our implementation schedule.

## Implemented

- Payments, Debt, Bonus, Devices, Login history, Revenue and Reservations load only when selected, through the existing cookie-based API client.
- Payments, login history and reservations use server pagination (10 records per page). Payment failures show the server's failure reason.
- Every tab includes loading, error/retry and empty handling; revenue displays genuine zero totals.
- Debt shows outstanding amount, paid/unpaid records and dates. Pay all requires debts.edit permission, a confirmation and a fresh debt snapshot check. Duplicate submissions are locked.
- After POST /api/admin/users/:id/debt/pay, the debt resource is fetched again. A successful write followed by failed refresh is reported separately, with no optimistic paid-state changes or automatic retry.
- Customer profile and document images from the previous day's local improvements are included in this branch. Images have inline previews, safe HTTP(S) URLs, no-referrer requests and missing/broken-image fallbacks.

## Actual backend contracts

All paths start with /api/admin/users/:id.

| Resource | Response |
| --- | --- |
| payments | data, total, page, pageSize; amount, currency, status, transactionType, failureReason |
| debt | userId, totalDebt, currency, debts; each record includes isPaid and paidAt |
| bonus | userId, balance, currency, history |
| devices | Array; model, platform, appVersion, lastSeenAt, isCurrent, deviceId |
| login-history | Paginated data; at, ip, device, platform, city, success |
| revenue | totalRevenue, totalRentals, averageRentalValue, currency |
| reservations | Paginated data; carName, plateNumber, reservationDate, status, totalPrice and delivery fields |
| debt/pay (POST) | success, paidCount |

The mock always returns an empty bonus history; no entries are fabricated. Device/login data can be regenerated by the mock on refresh. Document URLs may point to generic placeholder images rather than actual documents.

Pay all marks every currently unpaid debt as paid. It does not create a rental payment or change PaymentPending rentals. A preflight snapshot detects changes while confirmation is open, but cannot make the GET/POST sequence atomic; a new debt arriving between those requests is a backend limitation.

- Filter controls share a height; UUID lookup is styled and validated. Images enlarge in a nested dialog with independent Escape handling.

- README reflects Day 12, explains isolated verification scripts and distinguishes implemented work from future modules.
