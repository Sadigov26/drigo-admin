# UI direction

The user prefers a practical admin interface with individually considered layouts.

- Keep page titles compact and labels direct. Avoid slogans, hero sections, decorative initials and roadmap cards.
- Show real data and working actions. Do not fill space with invented metrics or inactive buttons.
- Use system fonts, neutral backgrounds, subtle borders and modest corner radii.
- Reserve color for meaningful statuses and primary actions.
- Let each module's workflow determine its layout. Lists should prioritize filters, readable rows and useful actions.
- Keep code readable and easy to explain.
- Keep backend limitations and implementation notes in developer documentation, not in customer-facing help text. Use concise operational labels and units in the UI.
- Use available desktop width for tables and dashboards. Group detail fields by workflow; display named features without internal metadata.
- Keep Overview focused on the signed-in account. Add dashboard information only when its real API integration is implemented.
