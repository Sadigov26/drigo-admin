# Day 9 — Rentals list and detail

## Scope

- Rentals menu uses the existing `rentals.view` route guard.
- List: all six backend statuses, pagination and sort, customer/plate/ID search, start-date range in Dubai time, minimum/maximum elapsed hours, loading, empty, error and retry states.
- Detail modal: customer, car, tariff, debts, action history, start/end photos, retry state for PaymentPending and cancellation reason for Cancelled. Remaining backend fields are available under Additional rental details. Missing values render as a dash; zero and negative backend amounts are preserved.
- Payments sub-tab requests its own endpoint, displays amounts/currency, status, transaction type and Dubai-local timestamps. Expandable payment details preserve other fields.
- Route sub-tab loads the rental route lazily and renders a Leaflet polyline. The map is reused without inventing a speed field, since rental coordinates have none.
- This day is read-only: no end-rental, payment retry or status mutation calls.

## Real API verification

Authenticated curl was used for `GET /rentals?page=1&pageSize=2&status=Active`, `/rentals/1`, `/rentals/1/payments` and `/rentals/1/route`. Backend route and mapper source were also inspected.

List shape is `{ data, total, page, pageSize }`, with nested `user` and `car`. Detail has `tariff`, `debts`, `actionHistory`, `startPhotoUrls`, `endPhotoUrls`, `paymentRetryState` and `cancelReason`. Payments are an array. Route is `{ rentalId, distance, coordinates: [{ latitude, longitude, at }] }`.

Supported sort keys are startDate, endDate, status and totalPrice. The backend ignores search and has no duration/date-range parameters: with any of these local filters, the client collects all pages for the current status and filters the full result before local pagination. Requests are bounded and cancellable; duplicate/incomplete snapshots fail visibly rather than pretending to be complete. Without local filters, pagination stays server-side.

Duration means elapsed hours from startDate to endDate. Active/Started records without an end use a single timestamp captured when the request starts. Other missing/invalid durations are excluded only when a duration filter is active. Hour limits are inclusive. Date range filters the start date in Dubai (UTC+04:00), including the entire final day. Reversed ranges and malformed dates fail before a request is made. The handbook says duration but does not define a query or unit; the UI makes these semantics explicit.

The simulator can change records between requests. Route points are generated by the mock per request, not stored historical GPS. Photos are mock URLs from the backend, not real customer photographs. Only HTTP(S) photo URLs are rendered; text is React-escaped. All API calls use the shared cookie client and its 401 handling.
